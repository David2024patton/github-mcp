## H-4 first integrated slice — security triage and dependency review

`src/tools/security-read.js` supplies real bounded `github_security_list_alerts` and `github_security_get_alert` for Dependabot, CodeQL and secret scanning, `github_security_list_advisories` for repository or global advisories, and `github_security_compare_dependencies` for explicit refs or a verified PR.

`src/tools/security-alerts-write.js` supplies `github_security_update_alert`: explicit confirmation, production classification, kind-specific valid dismissal/resolution reason, single patch and exact sanitized readback; secrets are never journalled.

`tests/unit/h4-alerts.test.js` covers three transport doors, all three alert update variants, refusal of missing/wrong reasons, secret redaction in reads/results/journal, bounded advisory projections, exact PR revision resolution, request-shape validation and plan-limited 403 diagnostics. `npm run check`, full unit, shapes, DB and required exact-head review/CI remain merge gates. ## H-4 settings controls — second integrated source

The additional `github_security_get_settings` reads verified repository
security feature status and private/public eligibility, while
`github_security_set_feature` preflights the exact feature, writes only the
named setting and independently checks every other visible security flag
remained unchanged. New paid features on private repositories **fail closed**
without an independently verified billable-committer count and a separate
owner budget decision; no price or owner approval is fabricated. Public/free
and disabling operations are guarded as production changes.

`github_actions_get_settings` reads all five official settings categories:
Actions enablement/allowed actions, workflow token permissions, selected
actions when enabled, fork contributor approval, and artifacts/log retention.
`github_actions_set_settings` accepts a single section and only the fields
that the caller names. It merges with the entire readable section, refuses
incomplete baselines, checks organization maximum retention and preserves
every other Actions setting after independent readback. Permission-expanding
changes always demand full-profile production confirmation.

Focused three-door contracts in `tests/unit/h4-settings.test.js` cover
security flags, full Actions policy read/merge/write, alternate readback,
provider request-shape validation, paid private refusal, retention limit,
and missing readable settings. These source tests are not provider
acceptance; connected read/write/denial/readback still requires exact
READY live ancestry and legitimate owner/permission gates. H-4 remains
IN_PROGRESS for independently priced private paid security capabilities,
provider acceptance, and any uncovered security toggle endpoints.
