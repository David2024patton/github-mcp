## Drift check A — current GitHub primary API contracts

| Approved assumption | Verified current provider behavior | Implementation |
| --- | --- | --- |
| GitHub App user/installation authorization accesses notification inbox | Current REST notification endpoints explicitly reject GitHub App and fine-grained token types | Require optional classic \`K\` token with notifications scope (owner IN-11 remains optional and pending), guide to setup if absent, never mint token |
| An HTTP 202 marks all notifications read instantly | GitHub may schedule inbox change asynchronously | Independently poll by a new bounded read within the normal readback; unresolved after request = unconfirmed, not successful |
| A read mark is equivalent to Done | Thread read PATCH and done DELETE have different API semantics | Exact thread action choice, explicit scope (thread/repository/all); use readback of unread or absence |
| Notification subscription is global only | GitHub supports separate user repository and thread subscription resources | Exact scope and ID, subscribed/ignored state, independent GET after PUT or DELETE |
| Gist update can toggle public/secret setting | The create endpoint accepts public; update edits description/files but not visibility | Require public decision only on create; existing visibility immutable; public create classified as access-widening |
| Omitting a file from an update deletes it | GitHub retains omitted files, deleting one requires its name with null | File change map with explicit null removal; verify changed/removed files, preserve unmentioned files |
| Gist GET always has complete content | GitHub may return truncated files and up to 1MB per file | Never fetch raw URLs; cap each file excerpt at 16KiB and combined to 64KiB; explicit truncated/complete flags |
| An absent classic token blocks all O-7 work | Gists use **U** token, separate from K | Split scope/credentials so available gist operations continue independently |
| A successful gist deletion establishes permanent absence | External provider state may lag or return unexpected result | Read exact gist ID again; mark unconfirmed unless provider proves not found |

## Connected outcome

\`src/tools/notifications-gists.js\` registers all seven existing catalog tools:
\`github_notify_list\`, \`github_notify_mark\`, \`github_notify_set_subscription\`,
\`github_gist_list\`, \`github_gist_get\`, \`github_gist_save\`, \`github_gist_delete\`.

The notification inbox supports bounded unread/all inventory, optional repository and participation filters, confirmed mark-all or repository read and exact thread read/done, and thread/repository subscriptions. Classic access absent is explicitly an optional owner setup choice and never triggers token acquisition. Gist lifecycle accepts exact file names, content updates and removals, rejects oversized/ambiguous operations, preserves public visibility, and verifies user-owned mutations. All four writes share the production/confirmation, access, protection, durable journal, replay and readback gates.
