## Drift check A
| Assumption | Verified on baseline | Decision |
| --- | --- | --- |
| Run ledger and per-step claims exist | `runDevMutationOnce`, `createOwnedFixtureBranch`, `commitOwnedFixtureFile`, `createOwnedDraftPr` (V-1) | Reuse unchanged; no new migration |
| Standalone cleanup handles test branches/PRs | `inspectTestResources` accepts only pr, branch, label, pr_label, issue and requires a branch to remain at its creation SHA | A branch that carries the fixture commit would be uncleanable; extend with the exact recorded fixture-file commit as the expected head, and accept fixture_file, workflow_run, check_run |
| `rtc-run` label is repository-wide | `createOwnedRunLabel` always creates `rtc-run`, so a second run in a shared host repo would collide | Optional per-run label name `rtc-run-<runId>` (cleanup already allows it); default unchanged for seeds |
| Dispatch returns the run ID | pinned description: `workflow-dispatch-response` carries `workflow_run_id` | Journal it as a `workflow_run` object before any wait |
| Cleanup lists at most 50 rows | `planDevCleanup` refuses >=50 | V-3 tools stop at 40 recorded objects per run |
| Seeded scenario runs have finite resource bounds | `assertScenarioResourceBounds` | V-3 never adds to a run bound to a seed scenario |

## Build contract
- `src/dev/test-refs.js`: shared preview/host/run guards (`readTestRun`, `assertRoom`), name patterns, `branchOf`.
- `src/tools/dev-test-write.js`: `github_dev_create_test_branch`, `github_dev_open_test_pr`.
- `src/tools/dev-ci-write.js`: `github_dev_dispatch_and_wait`, `github_dev_set_check_run`.
- Cleanup: `src/dev/cleanup-non-scratch.js` handles workflow_run (cancel if running, delete the exact run, read back absence), check_run (close out only; GitHub has no delete, reported as retained), fixture_file (removed with its deleted branch).
- Safety: preview connections only; `declarations.production:'never'` plus `productionReason` on the new ref and `workflowProduction` on dispatch; locked/pr-only protected repositories are refused by the existing guard list (the V-3 tools are not conveyor tools); every GitHub write is one claimed durable step, uncertain outcomes never replay.

## Named tests
`tests/unit/dev-test-write.test.js`, `tests/unit/dev-ci-write.test.js` (nine-check contract through all three doors for each write tool plus the named refusals), `tests/unit/dev-cleanup-non-scratch.test.js` (extended). Shapes validated by the fake GitHub against the pinned description.
