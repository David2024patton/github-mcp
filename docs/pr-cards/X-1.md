# X-1 — Undo one finished change

**Status:** MERGED (bundle-3 PR #224). Approved design: `docs/designs/BATCH-X.md` X1; roadmap map `docs/implementation-contracts/REMAINING-WORK.md` X-1.

## What it does (plain words)

`github_undo_change` takes a change number from `github_recent_changes`. If that change was finished, confirmed by reading it back, and recorded a clean opposite, it runs the opposite through the **same guarded tool** (preview, then confirm). Nothing in the undo tool talks to GitHub itself.

## Safety decisions

- Unknown numbers and other accounts' changes get the same answer ("no change number N on your accounts"); history is not probed.
- Previews, refusals and unconfirmed changes are refused: what happened is unknown.
- A change that was followed by a newer real change to the same repository and tool family is refused, naming that change, so an old undo cannot overwrite newer work. This also stops the same change being undone twice (the first undo is itself a newer change). If 100 newer changes exist the change cannot be proven current and is refused.
- A production change cannot be undone from a preview connection; the target tool re-applies every production, profile, protected-resource, people and spend check.
- The stored opposite may not carry its own `confirm`, `dryRun` or `requestKey`; the caller decides. The default retry key is `undo-<number>`.
- Undo of an undo works because the undo is an ordinary change with its own recorded opposite.
- Changes with no opposite say what to do instead: merges (revert PR), releases, repository delete/transfer, secrets (setup page), invitations (cancel), spend, deleted runs/logs/artifacts/packages.

## Acceptance evidence

`tests/unit/undo.test.js` (ten tests through the real dispatcher with the real archive tool): preview/ask/confirm, undo of an undo, no double undo, newer-change refusal naming it, unrelated families not blocking, no-opposite advice, foreign/unknown/preview-only/unconfirmed refusals, preview-mode production refusal, profile refusal, damaged opposite and self-approval refusal. `scripts/check-writes.mjs` pins the tool's catalog safety. Live acceptance (an undo on a scratch account) stays in the release acceptance queue.

## Known limit

Changes made on GitHub outside this server are invisible to the newer-change check; the target tool's own read-before-write still compares current state for each tool that does so.
