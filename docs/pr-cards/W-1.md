## Contract and request seams

1. `github_workflow_pr_status({owner?,repo,number})` is a read-only, compact tool for Builder/Operator. Calls `github_pr_get`, then bounded `github_pr_list_stacks`; reports known state and actionable next operation. Both reads remain through the authenticated registry.
2. `github_workflow_open_pr({owner?,repo,head,base?,title,body?,draft?,labels?,confirm?,dryRun?,requestKey?})` is a composed guarded workflow for everyday/full Builder, NOT a raw write. Validates authorized default branch by `github_repo_get`, existing matching PR by `github_pr_list` (full detail and capped), then delegates one `github_pr_create` or `github_issue_set_labels`. No direct Octokit access.
3. Do not automatically add labels to an unconfirmed creation. The returned checkpoint explicitly directs caller to invoke again; if the underlying writer refused, previewed, timed out or lacked independent confirmation, never say opened. Branches are not pushed.
4. No SQL/migration. Profile, confirmation, notifications, outsider access, request key replay, network denial and result limits remain entirely under original wrappers.
5. Time budget: use `ctx.now` and refuse a new write after 46 seconds. A resumed invocation rechecks provider state. No CI polling loop.
