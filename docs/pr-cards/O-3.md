## Drift check A

| Design prerequisite | Observed provider/request behavior | Resolution |
| --- | --- | --- |
| Team/repository authorization is read as one flat list | GitHub team membership and team-repo grants have separate endpoints | Fetch exact scoped team, members and repository inventory with truncation status |
| Member list contains actual roles | Team list entries do not guarantee a trustworthy member/maintainer role | \`github_team_get(includeRoles=true)\` independently reads exact team membership per member |
| Custom organization roles exist on every account | Role endpoint responds 422 if not enabled/plan-limited | Return explicit plan-limited diagnostic; no role grant without exact role ID and current holders |
| Team membership is the same as organization membership | GitHub can invite a nonmember when added to a team | Require active org membership before any team add/update; never silently send an invitation |
| Team grant GET gives effective role | Repo grant check may only give 204, not full role | Read complete team repository inventory; verify requested role and unrelated permissions |
| A confirmed POST/PUT/DELETE proves state | Provider may be eventually consistent; membership invitation may be pending | Require independently observed exact ID, role, assignment/grant or absence; mark uncertainty |
| Team slug remains stable after rename | GitHub generates/changes slug from display name | Resolve saved response slug and ID, verify; no guessed rename result |

## Frozen batch subsection

**O-3** is the whole predefined batch subsection, counting **one** only after
source, required gates and merge succeed. It contains nine related tool
contracts: \`github_team_list\`, \`github_team_get\`, \`github_team_save\`,

\`github_team_set_repo_access\`, \`github_role_list\`,

and test cases are **not** separate subsections.

## Source deliverables

- \`src/tools/team-role-read.js\` and \`team-role-write.js\` expose explicit
  enrolled org-scoped reads and six bounded write lifecycles; optionally
  hydrate exact member roles and role holder assignments.
- Team save respects existing property values and exact provider response
  slug; deletion warns about membership and inherited repository access.
- Membership updates refuse an absent active org member; access-widening and
  notifications are classified. Team grant access is exact-repository-bound;
  it preserves every other observed grant and refuses truncated inventories.
- Organization role ID read first; plan and permission limits fail closed.
  Adding or removing exact user/team role assignments is read back, and
  journaled with one retry key.
- Every mutation traverses the existing confirmation, production, spend,
  protected-resource and output-redaction gates; no direct external writes
  are authorized by source implementation.
