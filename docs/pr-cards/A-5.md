## Drift check A

| Card assumption | Actual | Kind | Correction / test |
|---|---|---|---|
| Stripe's one-time store is copyable | It hard-codes `stripe-once`, `stripe_account`, `mode` and `/api/stripe/setup` | semantic (ours, small) | `createOneTimeStore({ db, service, setupPath })`; the AAD is `<service>-once/<id>/<account>/<kind>`; GitHub's column is `account`, no `mode` |
| The installation-token call goes through `githubFor` | `githubFor` needs a token first | semantic (small) | `bareOctokit({ token, fetch })` in `client.js` (same version header and user agent; no database hooks, no throttling, no retries) for the App-JWT calls |
| `@octokit/auth-app` mints tokens | It brings its own cache and real-network `request`; the injected-fetch seam is awkward | mechanical | JWT signed with `node:crypto` (RS256, backdated 60 s, ≤ 10 min); the call is an ordinary typed request, validated by the fake against the description |
| Catalog credential letters | `I` installation, `U` user, `K` classic notifications token (not fine-grained) | none | `token({ account, cred })`: `I` = App installation token, or the fine-grained token when `credential_kind = 'fine_grained'`; `K` = classic |
| Body schemas validate in the fake | Schemas with `$ref` failed to compile when taken out of the document; JSON bodies were being type-coerced | bug in A-4's test helper | Compile through a pointer into the registered document; coercion only for query strings (test in `fake-github.test.js`) |

## A-5a — built (#11)

- `src/core/crypto.js` (copied, AES-256-GCM with a context per value), `src/core/one-time-secrets.js` (parameterized, ten minutes, read-and-delete).
- `src/db.js` + fake: `saveApp`/`getApp`, `upsertAccount` (first account is the default; never touches `production_enabled`, spend, credentials or the default
  flag of an existing account), `getAccount`, `listAccounts` (no ciphertext), `setInstallation`, `setInstallationStatus`, `setUserAuthorization`, `clearUserAuthorization`,
  `setFineGrainedToken`, `setClassicToken`, `setAccountPlan`, installation-token cache (`getInstallationToken` only if > 5 minutes remain), setup states (single use, bound to
  a purpose, expiring), one-time secrets (atomic delete-and-return, purge ≤ 100 expired per write).
- `src/github/credentials.js` `createCredentials({ db, env, fetch, now })`: `token({ account, cred, scope })` (what `githubFor` calls), `storeApp`, `webhookSecret`,
  `clientCredentials`, `appJwt`, `storeUserAuthorization` (refresh ten minutes before expiry; a lost race uses the other instance's new tokens; a refused refresh clears it),
  `storeFineGrained`, `storeClassic`, `forgetUserAuthorization`, `sealVerifier`/`openVerifier`, `keyConfigured`. Every value is sealed with a context tying it to its account/App/installation/scope.
- Tests: `credentials-contract.js` (fake + Postgres), `tests/unit/{crypto,credentials,credentials-store}.test.js`, `tests/db/credentials.test.js`.
