## A-5a — built (#11)

- `src/core/crypto.js` (copied, AES-256-GCM with a context per value), `src/core/one-time-secrets.js` (parameterized, ten minutes, read-and-delete).
- `src/db.js` + fake: `saveApp`/`getApp`, `upsertAccount` (first account is the default; never touches `production_enabled`, spend, credentials or the default
  flag of an existing account), `getAccount`, `listAccounts` (no ciphertext), `setInstallation`, `setInstallationStatus`, `setUserAuthorization`, `clearUserAuthorization`,
  `setFineGrainedToken`, `setClassicToken`, `setAccountPlan`, installation-token cache (`getInstallationToken` only if > 5 minutes remain), setup states (single use, bound to
  a purpose, expiring), one-time secrets (atomic delete-and-return, purge ≤ 100 expired per write).
- `src/github/credentials.js` `createCredentials({ db, env, fetch, now })`: `token({ account, cred, scope })` (what `githubFor` calls), `storeApp`, `webhookSecret`,
  `clientCredentials`, `appJwt`, `storeUserAuthorization` (refresh ten minutes before expiry; a lost race uses the other instance's new tokens; a refused refresh clears it),
  `storeFineGrained`, `storeClassic`, `forgetUserAuthorization`, `sealVerifier`/`openVerifier`, `keyConfigured`. Every value is sealed with a context tying it to its account/App/installation/scope.
- Tests: `credentials-contract.js` (fake + Postgres), `tests/unit/{crypto,credentials,credentials-store}.test.js`, `tests/db/credentials.test.js`.

## A-5b — built (#12)

The setup page and the three GitHub redirects, with the webhook and the two server tools split into A-5c (a third PR keeps each under the size limit).

- `src/github/app-manifest.js`: the permission lists (`REPOSITORY_PERMISSIONS`, `ORGANIZATION_PERMISSIONS`, `MANIFEST_PERMISSIONS`), `isValidLogin` (no leading or trailing hyphen), `appNameFor` (`robinson-mcp-<login>`, at most 34 characters), `buildManifest`, `manifestFormUrl`, `installUrl`. The App is private, subscribes to no events yet, and asks for no account-level permissions (deferred to Batch O).
- `src/github/setup-page.js`: `createSetupHandlers({ db, credentials, oneTimeStore, env, fetch })` → `setup`, `manifestCallback`, `userCallback`. Every post needs the same origin, the double-submit CSRF token and the administrator passphrase (the connector login's five-wrong-in-fifteen-minutes lockout); every credential step needs `VERCEL_ENV=production` and the encryption key.
- `src/github/setup-readback.js`: after each step the page asks GitHub what is true now (App, installation, missing permissions, owner sign-in). `src/github/setup-html.js`: escaped plain-language page, no script.
- `src/github/routes.js` + `api/github/[action].js`: one serverless function for `setup`, `manifest-callback`, `user-callback` (Vercel Hobby caps functions at 12; the webhook in A-5c is the only other file in `api/github/`). `src/runtime.js` `getSecretsRuntime()` builds the credential and one-time stores per instance.
- `src/github/client.js` `bareOctokit` now accepts no token, for the unauthenticated manifest conversion.
- Tests: `setup-page` (27: origin/CSRF/passphrase/lockout, preview refusal, missing-key message, state reuse and wrong purpose, manifest conversion with a fake GitHub, install return read as the App, PKCE exchange, fine-grained and classic acceptance and refusal, one-time reveal, escaping, secret-shape scan of every page), `app-manifest`, `github-routes`.
- **Not yet verified against real GitHub** (needs IN-02…IN-05): that GitHub accepts every permission name in the manifest. Seven names exist only in GitHub's docs data, not in the REST description (see the test in `app-manifest.test.js`); if the real creation rejects any, remove it there.

## A-5c — built (#14)

- `api/github/webhook.js` (own file, `bodyParser: false`) → `src/github/webhook.js` `createWebhookHandler({ db, credentials })`, `verifySignature`, `readRawBody`. 401 (one answer) for bad/missing/malformed signature, unknown App or bad App id; 405 non-POST; 413 over 1 MB; 400 signed non-JSON; 503 without detail.
- Events handled: `installation` created / deleted / suspend / unsuspend / new_permissions_accepted, `installation_repositories`, `github_app_authorization` revoked. Lookups use `db.listAccounts()` (no new database method); an account is only touched when its `app_id` is this App.
- `src/tools/server.js`: `github_whoami`, `github_list_accounts` (handlers `(args, ctx)` with `ctx = { connection, db }`), registered in `src/tools/index.js`.
- Tests: `tests/unit/webhook.test.js`, `tests/unit/server-tools.test.js`.
