## Part 1 — release metadata reads (#54)
- `src/tools/releases-read.js` exports `releaseList`, `releaseGet`, `releaseView`, `tools`, `handlers`.
- `github_release_list`: `GET /repos/{owner}/{repo}/releases`, bounded page/per_page and possible-next-page without invented total; summary includes tag, draft/prerelease, publishing time and asset count.
- `github_release_get`: exactly one of selector=id/tag/latest; GET routes `/releases/{release_id}`, `/releases/tags/{tag}`, `/releases/latest`. 404 is not_found; permission failures remain errors. Assets returned as metadata and download links only, capped at 100; no bytes in tool.
- `src/tools/index.js` registration, `tests/unit/registry.test.js` expected names; `tests/unit/releases-read.test.js` request-shape, pagination, selectors, 404/403 and refusal fixtures.
- No production changes, no tag write, no release asset download, no new migration.

## Part 2 — guarded lifecycle (later PR)

## Part 2 implementation evidence (#55)
- `src/tools/releases-write.js` exports `github_release_create/update/delete` with the existing nine-check `defineGithubWrite` gates. Draft and generated release notes are defaults; production mutations require independent approval. Duplicate/missing/immutable published releases refuse. Create verifies GitHub ID and draft/tag; update PATCH includes only named editable fields and verifies preserved state; delete verifies release absence and never touches the tag. Automatic rollback is not promised.
- `tests/unit/releases-write.test.js` covers all three doors for each write, plus draft defaults, production refusal, duplicate tags, draft publication, immutable refusal, missing IDs and exact read-back mismatch. No live GitHub tokens.
- G-5 remains IN_PROGRESS: URL-safe asset upload remains a separate follow-up; notes preview is #57 and asset deletion is #56.
