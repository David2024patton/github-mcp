## Outcome

One new catalog section, "Skills catalog", area `skills`, with three tools (`github_skills_search`, `github_skills_route`, `github_skills_execute`) fed by a generated metadata-only catalog of David Patton's MIT-cleared skills, shipped switched off (`SKILLS_CATALOG_ENABLED`), visible to owner connections and to tenants named in `SKILLS_CATALOG_TENANTS`, with GitHub-family execution run step by step through this server's existing guarded tools under a plan confirmation bound to a payload hash.

## Acceptance criteria

1. The catalog data module is generated by `scripts/build-skills-catalog.mjs` from David Patton's `registry.json` at a pinned snapshot named in the generated file's header, and it contains **zero** `not-cleared` records.
2. Every catalog record carries only the agreed metadata (id, name, kind, category, description, keywords, risk class, license status, checksum). No skill body text and no file path from David's repository appears anywhere in this repository or its database.
3. `github_skills_search` and `github_skills_route` refuse with the standard structured refusal while `SKILLS_CATALOG_ENABLED` is not `enabled`, and refuse callers who are not entitled (owner connections, and tenants listed in `SKILLS_CATALOG_TENANTS`, only; RTC passes get nothing).
4. `github_skills_route` executes nothing. For a GitHub job it returns a stored decision (per connection, 30-minute expiry) with the plan's step names and a confirmation object carrying `payload_sha256`; under the confidence threshold it returns an `ask` decision instead of guessing.
5. `github_skills_execute` refuses without `confirm: true`, refuses when the supplied `payloadHash` does not match the stored decision's `payload_sha256`, and refuses an expired, already-used or other-connection decision. On success it runs the plan's steps **only** through the existing guarded tools (each step keeps its own preview, confirmation, request key and read-back), and consumes the decision exactly once.
6. Execution results pass the overlap check against the packaged corpus, and the planted-canary test proves a planted skill-text string is blocked and never appears in a result. Decisions, results and logs carry skill ids and step names only.
7. No new credential storage exists. Delegated steps resolve the calling connection's own credentials exactly as a direct call does today, with no fallback to another user's credential or an operator credential.
8. `python3 scripts/count-catalog.py`, `python3 docs/pr-cards/validate-index.py`, `npm run check` and the unit tests are green at the exact head.

## Tests

- `tests/unit/skills-catalog.test.js` (new): the generated catalog loads and validates; zero not-cleared records; only the agreed metadata fields are present; search filters by entitlement and maximum risk class.
- Route tests: a GitHub job returns a decision with step names and a `payload_sha256`; a low-confidence job returns `ask`; route executes nothing.
- Gate tests: search, route and execute all refuse while the section is disabled, and refuse unentitled callers and RTC passes.
- Execute tests: refusal without `confirm: true`; refusal on a mismatched `payloadHash`; refusal on an expired, consumed or other-connection decision; a confirmed plan calls only guarded tools and consumes the decision once; the write-contract checks every write tool passes.
- Anti-extraction test: a result containing the planted canary string is blocked, and the canary never appears in any returned result.
