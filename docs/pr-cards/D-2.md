## Built (part 2)

`src/tools/code-write.js`: `github_content_put_file`, `github_content_delete_file`, `github_content_push_files`, `github_commit_comment`, `github_git_update_ref`; `src/tools/github-write.js` holds the helpers shared with D-1 (`octo`, `slug`, `missing`, `refusal`).
Decisions: a branch must always be named for a file or commit write (no guessed default), and the branch is the write's target so production names, protected branches, project-owned refs and the protected list all apply. `expectedSha` (file version from the preview) makes a stale file write refuse with the new version; `expectedHead` (branch head) and `expectedSha` (ref value) do the same for commits and ref moves, on top of GitHub's own `expectedHeadOid` / `beforeOid`. The undo of a file update restores the previous text (audit G17); the undo of a new file deletes it; a ref move undoes by moving back with `expectedSha`. A move that drops commits needs `force: true` and the preview says how many would be dropped; a tag move is production; the default branch of a `pr-only` repository is refused by the real guard.
Drift notes: `updateRefs` needs the repository's node id (read from the repository) and returns no ref, so the result is read back from `git/ref`; `createCommitOnBranch` returns the new commit's oid, which the read-back compares with the branch head.
Tests: `tests/unit/code-write.test.js` — the nine write-contract checks through all three doors for each tool (123 tests) plus the extra D-2 checks.
