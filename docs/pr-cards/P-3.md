## Acceptance and integration boundary

- Actual main: `ed095fbd3308f70c933d6d082d35e9c093bf9cdc` after P-2 merge. PR #208 was concurrently opened as a separate owner-guidance update; preserve and reconcile before merging this PR.
- A project spec requires concrete owner/repo/name/visibility/required checks; optional production branch, environments and supplied workflow findings. Unknown findings cause explicit error, not invented observations. A pure `github_profile_draft` returns an inactive validated v1 profile and APP-NEEDS text, never fetching or committing code.
- Draft profile rows are revisioned in known_projects, status=draft, with nullable source SHA until a real initial branch is verifiable. An active profile still requires a real 40-character SHA. `createKnownProject` is insert-once, collision-safe and does not activate, overwrite or widen an existing policy; fake DB implements the same contract.
- The setup workflow is a resumable desired-state machine, never an unguarded batch. It first reads provider repository state: an existing nonempty repository without matching draft is a protected takeover attempt; no draft row or provider mutation occurs. It persists a draft checkpoint only after an explicit full-profile confirmation. A retry re-reads GitHub, chooses at most one missing stage and delegates its write through the existing guarded writer with its own production/access/spend/approval/confirmation/readback/replay checks.
- Stages: create an empty (uninitialized) repository, enable merge commit, create an exact required-check/no-bypass ruleset, add missing standard labels without overwriting custom labels, create requested non-production environments, enable public security scanning/push protection when eligible. Private paid security remains owner/provider blocked; production-like envs without specified reviewed policies remain needs_owner_review. No branch moves, workflow edits or repository documentation commits.
- A second run of completed provider state selects no write, returns its draft/doc and actionable outstanding owner review. Interrupted/uncertain writes require provider re-observation; no stage counter invents success.
