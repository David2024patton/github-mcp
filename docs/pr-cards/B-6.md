## Drift check A

| Card assumption | Actual | Kind | Correction / test |
|---|---|---|---|
| A `read_only` connection gets "every permission at `read`" | Two permissions exist only at `write` (`workflows`, `profile`); asking for them at `read` makes GitHub refuse | mechanical | They are left out of a read-only token. `WRITE_ONLY_PERMISSIONS` is checked against the vendored description by a test |
| Permissions subset comes from the App | An empty `permissions` object means "everything" to GitHub | semantic (ours) | The subset is built from the installation's stored permissions; if they are unknown the token is refused (never an empty list) |
| Tools carry `profiles` metadata | Only write tools do | none | Read tools are visible to every profile; a write tool only to the profiles it lists |
| Hidden tool refused by name | The dispatcher answered with the write layer's profile message | none | A hidden write tool now answers "Unknown or unavailable tool" before anything runs |
| Fine-grained tokens | Cannot be narrowed per connection | none | Unchanged limit, documented: for an account on a fine-grained token a `read_only` connection relies on the profile checks and the write layer only |

## Built

- `src/core/registry.js`: `isToolVisible`, `toolsForProfile`, `profileCounts`. `src/core/mcp-server.js` lists only the tools the connection's profile may see; `src/tools/dispatch.js` refuses a hidden tool by name.
- `src/github/credentials.js`: `token({ account, cred, scope, profile })`; for `read_only` the installation token is minted with every granted permission at `read` (write-only ones omitted), cached under its own scope key; `src/github/client.js` passes the connection's profile.
- `api/index.js`: home page prints `tools_by_profile`.
- Tests: `profiles` (10); updated `client` and `server-tools`.
