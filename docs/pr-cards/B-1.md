## Built

- `src/core/write.js`: `defineWrite(spec)` (contract-generic; GitHub is never imported). Order: connection and target checks, read, classify, refuse what the connection's mode forbids, gates, preview, `dryRun`, ask first, claim the request key, send once, read back and verify, finish the row with its inverse. `normalizeClassification`, `marksOf`. Result `status`: `preview`, `needs_confirmation`, `refused_by_guard`, `applied`, `unconfirmed`, `rejected`, `uncertain`, `replayed`, `refused`.
- `src/core/validate.js`: argument checking for the JSON Schema subset the tools use; the dispatcher uses it for every call.
- `src/tools/define-github-write.js`: GitHub's request key, `classifyGithubError` (a 4xx or a client error is a definite "no"; anything else is uncertain), short plain `explainGithubError` (B-5 adds the full rule set).
- `src/tools/gates.js`: the ordered gate list (empty until B-2). `src/tools/dispatch.js` (`createDispatch`) now runs write tools with credentials and gates; the layer itself refuses a profile that may not change anything.
- `src/db.js` + fake: `recordChange`, `claimChange`, `finishChange` (`releaseKey` frees the key after a definite rejection), `getChange`; unique index `change_log_request_once`.
- Tests: `change-log` contract (fake and Postgres), `write-contract` (the nine checks x five sample tools x two doors = 74), `write-core` (14), updated schema and registry tests. Mutation checks: removing the mode refusal, the ask-first rule, the replay claim or the read-back comparison each fails the contract.
