## Source slices and observable acceptance

1. **H-3 access inventory:** `github_collab_list` reads actual bounded collaborator membership, permissions and pending invitations using the enrolled account. `github_deploykey_list` reads bounded key metadata, access modes and last-use, without returning raw SSH key data. Incomplete inventories are marked, not called complete.
2. **H-3 collaborator lifecycle:** `github_collab_add` preflights effective permission and invitations, confirms access widening/notifications and verifies either effective permission or an exact pending invitation. `github_collab_remove` checks direct membership and requires absence from both direct inventory and pending invitations after deletion; inherited organization permissions are explicitly reported.
3. **H-3 invitation management:** `github_collab_manage_invitation` checks the exact pending invitation ID/invitee and either updates permission or cancels. The readback must preserve identity and show the requested permission, or confirmed removal.
4. **H-3 deploy-key lifecycle:** `github_deploykey_add` accepts only a single syntactically public SSH key line, hashes public material for duplicate detection and journal identity, and independently reads new key identity/access mode. Private key headers/newlines are rejected without echo. Write-capable keys are production and access-widening; read-only keys still require access-change confirmation. `github_deploykey_delete` requires exact numeric ID and verifies absence.

All five write tools use `defineGithubWrite`, stable request-key journal claims, three transport doors, access/production/confirmation and protected-resource gates. No nonproduction fixture is allowed to stand in for connected-provider behavior. The new source does not activate production, broaden OAuth permission, spend, or bypass owner approval.
