# X-2 — Read-only smoke report

**Status:** MERGED for the engineering (bundle-3 PR #224). The report on the real accounts is an owner step (`docs/OWNER-INPUTS.md` IN-04/IN-05) and stays in the release acceptance queue. Approved design: `docs/designs/BATCH-X.md` X2.

## What it does (plain words)

`node scripts/smoke-readonly.mjs --account <login> [--repo <name>] [--fixtures file.json]` runs every read tool once on a preview, read-only connection and writes `docs/audits/smoke-<date>.md`: PASS, LIMITATION (a GitHub plan feature the account lacks), GAP (a permission not granted), SKIPPED (no safe example argument) or FAIL, with GitHub's request ID.

## Safety decisions

- Refuses to run unless the connection is preview mode with the read_only profile.
- Only plain read tools are selected; changes and composed runners are never called.
- The network function given to the server refuses every request except GET, HEAD and GraphQL queries before any bytes leave (defense in depth). Credential minting is the one POST outside it, and it changes nothing in a repository.
- Arguments come only from the owner's fixtures; a required argument with no fixture is SKIPPED, never invented.
- The report records status and request IDs only; no header that could hold a credential is kept.

## Acceptance evidence

`tests/unit/smoke-readonly.test.js` (eight tests): wrong mode, read-only selection, no invented arguments, outcome classification with request IDs, write blocking, GraphQL query versus mutation, report content without credentials. Not run against a real account in CI or by the build session.
