## Drift check A

| Card assumption | Actual | Kind | Correction / test |
|---|---|---|---|
| Delete is `DELETE …/git/refs/heads/{branch}` | The description's route is `DELETE /repos/{owner}/{repo}/git/refs/{ref}` with `ref` = `heads/<branch>` or `tags/<tag>` | none | Used as such; the fake validates the shape |
| "Default branch delete always refused" is a guard | The guards decide production, not per-tool bans | none | The tool reads the default branch and refuses in `apply` before any request, even on a production connection with confirm (tested); the preview says it can never be deleted |
| Branch create defaults to the default branch | Needs the default read from GitHub, and a start that may be a tag or commit | none | Start resolved through `GET …/commits/{ref}`; test: default `trunk` is used, never `main` (audit G4) |
| `github_branch_list` never sends an empty `protected=` | Octokit sends whatever it is given | none | `protected` is added only when the caller gives a boolean (audit G9 test) |
| Tag create is two requests when annotated | `POST git/tags` then `POST git/refs` | none | Both through the one write; the ref points at the tag object; undo = `github_tag_delete` |

## Built

`src/tools/branches.js`: reads `github_branch_list`, `github_branch_get`, `github_tag_list`; changes `github_branch_create` (not production), `_rename` (full profile), `_delete`, `_merge` (production only when the receiving branch is), `github_tag_create`, `github_tag_delete` (always production, full profile). Inverses: create↔delete, delete→recreate at the recorded commit, rename back, tag create→delete. Branch or tag is the write's target, so production names, protected branches, project-owned refs and the protected list all apply.
Tests: `tests/unit/branches.test.js` (134): the nine write-contract checks through all three doors for each change tool plus the extra D-3 checks.
