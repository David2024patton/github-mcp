## Part 1 (built)

- `github_variable_list` (values shown; variables are not secret), `github_variable_set` (creates or updates; organization variables take `visibility` and `selectedRepositoryIds`), `github_variable_delete` (confirm always; the old value is kept in the undo).
- `github_secret_list`: names, dates and (for an organization secret limited to chosen repositories) which repositories can use it, for Actions, Dependabot, Codespaces and agent secrets; repository, environment and organization levels. Never a value.
- Production: the organization level, and an environment named like production (or with reviewers / a wait timer), is production work (confirm, production connection, refused under pr-only).
- Tests: `tests/unit/variables.test.js` — write contract through three doors for set and delete at repository, production environment and organization level; create-vs-update, undo, visibility rule, secret list never shows values.

## Part 2 (built)

- `github_secret_set`: default `valueFrom: setup-page` records a `secret_entry_requests` row (30 minutes) and returns a link with a one-use id; `valueFrom: generate` makes a random hex value on the server, seals it with the place's public key (libsodium `crypto_box_seal`) and sends it. No argument takes a value; the change log stores only that a request or write happened.
- `github_secret_delete` (value cannot come back, so no undo) and `github_secret_set_repo_access` (organization, always production, widening when repositories are added; undo restores the previous list).
- Setup page: `?secret=<id>` shows where the secret goes and a password box; `enter-secret` needs the passphrase, production deployment, a waiting request (claimed atomically, put back if GitHub refuses), not on the protected list, and production turned on for production-type places. The value is sealed and sent, never stored or logged.
- Tests: `tests/unit/secrets.test.js` (write contract ×3 doors for generate and delete at three levels, repo access; no tool argument takes a value; generated value absent from results and log), `secret-seal.test.js` (round-trip with a real key pair, every route), `setup-secret.test.js` (page flow, refusal cases, value absent from page, headers and change log), `secret-requests.test.js` + `tests/db/secret-requests.test.js` (fake and real Postgres).
- Not built (ROADMAP): showing a generated value once on the one-time page.
