## Built (part 1)

`src/tools/pulls-merge.js`: `github_pr_merge` (needs `expectedHeadSha`; refuses when the head moved, closed/merged, draft, GitHub says unmergeable, checks not green or unverifiable; merges with `sha` = the expected head and a merge commit by default), `github_pr_merge_async` (same plan, GitHub merges in the background with `direct_merge`), `github_pr_set_auto_merge` (on needs the head; off does not). All confirm-always and production when the base is the default or a protected branch.
Tests: `tests/unit/pulls-merge.test.js` (77): the nine write-contract checks × three doors for each tool plus every refusal reason, default and squash methods, preview connection refused for a default-branch merge, async pending / already pending / failed, auto-merge on and off with schema-valid GraphQL, and the no-bypass source check.

## Part 2 (built #48) — stacks
Baseline inspected: `06768ae49678d404a239c77f9e2341f816811a1e`. Routes verified against GitHub's 2026-03-10 REST stack reference (see design E0 E2).
Read only: BATCH-E E2/§3, TOOL-RECIPES §§2–4, `src/tools/pulls-write.js`, the existing write-contract helper.
- `src/tools/pulls-stacks.js`: list/filter/page/get stacks, create/append/dissolve stack; target uses the real owner/repo.
- Create and add fetch each numbered PR first, refuse duplicates, stale expected heads and a broken base/head chain; GitHub also validates atomically and may return 409/422. No stack operation merges, retargets or edits a branch.
- Unstack may leave locked PRs; independently read the remaining stack or its 404 and report exactly how many PRs were removed. No inverse promised.
- `tests/unit/pulls-stacks.test.js`: contract through handler/dispatch/github_call for create/add/unstack; read paging and 404; stale/invalid chain refusal; partial unstack; GitHub request-schema validation.
Validation: `npx vitest run tests/unit/pulls-stacks.test.js tests/unit/write-contract.test.js`, `npm run check`, `npm test`, `npm run test:shapes`; exact-head CI required.
Forbidden effects: no bypass, no automatic merges or branch mutation, no write for dryRun/refusals. Successor G-4 inherits the same write-contract and production-classifier conventions.
