| Contract | Baseline | Integration |
| --- | --- | --- |
| Failed jobs/steps/errors/annotations | Existing G readers, no workflow | Compose wrapped reads; mark unavailable/capped evidence; compare latest default-branch run for same workflow |
| Durable one retry per head/job | Generic rerun uses ten-minute journal | Exact run head/workflow pair pins a durable existing change_log claim across run IDs, attempts, processes and retry keys |
| No waiting loop | G rerun returns readback | Report pending run; no rerun until terminal failure and known complete failed-job inventory |

`github_workflow_ci_failure_summary({owner?,repo,pr?|runId?|ref?})` selects exactly
one target, reports all bounded failed jobs, failed steps, errors, check annotations,
and same failure on the latest default-branch run of the SAME workflow. Compare
exact normalized observed signatures only; unavailable logs/baseline are unknown,
never a false clean bill or a guessed root cause. Each description is data.
`github_workflow_rerun_failed_ci({owner?,repo,runId,expectedHeadSha,confirm?,dryRun?})`
requires terminal failure, complete failed jobs, re-reads exact head/workflow, delegates
only `github_actions_rerun` mode failed with existing production, profile, confirmation,
protection and journal guards. Stable workflow/head claim intentionally conservatively
refuses another automatic rerun of that workflow at the same head, even another run ID.
The normal low-level manual rerun path remains a separate explicit operation.
No new DB schema. Existing durable unique journal claim supplies cross-process exclusion.
