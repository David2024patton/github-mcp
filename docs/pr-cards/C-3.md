## Acceptance — one coherent outcome

1. On standard standalone `?listing=compact`, the first tools/list page exposes a curated everyday developer path directly: repository/file reads, feature branch creation, multiple-file text and binary commits, PR lists/details/create, CI results and review follow-up. Preserve current meta tools and workflow tools. First page has no cursor and contains at most 40 tools for each profile.
2. The same catalog remains fully discoverable, with unchanged names/schemas/handlers/permissions. Read-only connections cannot see write tools; regular and full profiles see only the tools already authorized for their respective profiles. RTC Hub remains lazy/unchanged.
3. Keep the existing `compact < 5,000`-token budget, avoid raising it solely to promote more tools; test the curated count, exact membership, paginated catalog, profile visibility and no-change security. A failing budget means trim selections, not weaken safety.
4. Source unit and MCP endpoint tests, `npm run check`, required exact-head `ci` and `release-policy`, reviewed PR and status/owner docs. No automatic live promotion outside policy.
