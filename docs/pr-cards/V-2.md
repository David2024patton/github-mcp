## #85 — guarded scratch cleanup
- Confirm-always `github_dev_cleanup` via every normal write safety door; exact run-scoped recorded scratch repo only.
- Reject any remote repo with wrong privacy/full name/run marker; close run-recorded unmerged PRs by exact number, verify closed; delete only recorded repo, verify absence, mark every child removed only after parent absence; finalize run only when ledger complete.
- Fail closed on truncated, uncertain or foreign records. Partial failure remains `cleaning`, with explicit reconciliation and new request key for a safely approved retry. Fake GitHub request-contract tests and all required CI; no live connected acceptance.

## #86 — standalone test branches and draft PRs
- Existing `github_dev_cleanup` now distinguishes runs owning a private scratch repository from runs owning only test refs in an existing host.
- Standalone mode refuses all non-branch/PR resources and requires an exact run-namespaced branch; every branch gets independent default/protection/ruleset/owner-production-name checks, exact created SHA and deleted-ref readback. Close recorded, unmerged, run-marked PRs before branch deletion.
- Same independent confirmation, scoped run freeze, partial state and read-back requirements. Never DELETE host repo.

## #87 — recorded labels and associations
- Accept only exact `rtc-run` or `rtc-run-<runId>` labels whose live description still contains the run marker. Before removing a label, read a complete bounded listing of issues/PRs using it and refuse if any owner is outside the run journal.
- Close run PRs first, remove only the journaled `number:label` associations, delete run refs and then the run label. Every remote outcome is independently read back and each scoped journal object marked individually. Any truncated or repurposed label fails closed.
- No live operations; unsupported issues/check runs/files/forwarders remain pending in V-2.

## #88 — GitHub issue cleanup without deleting issues
- Close only a run-recorded issue whose original body still contains the run marker, not any GitHub PR/issue alias. Require a pre-existing `rtc-cleaned` repository label rather than silently creating a shared label.
- Close with `state_reason=not_planned`, then label `rtc-cleaned`, independently read back both effects before marking the scoped ledger row; partial failures preserve `cleaning` for explicit safe resumption.
- Never DELETE an issue, branch outside the run, or a host repository. Connected acceptance remains pending.
