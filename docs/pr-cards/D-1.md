## Built (part 2)

`src/tools/repos-write.js`: thirteen `defineGithubWrite` tools. Visibility, default branch, rename, archive, transfer and delete are always production and always confirm; settings are production only when a merge option changes (`productionReason` with kind `repo-settings`); creating public (or from a template as public) and making a repository public are access changes naming the risk ("anyone can read the code and its history, including old commits"); transfer and delete have no inverse; every other change records its inverse (previous settings/topics, old name, previous default branch, previous visibility, unarchive, previous property values, unstar). Fork and star use the owner's own sign-in (`U`); creating in a personal account does too (an installation token cannot create a user's repository).
Drift notes: the OpenAPI description only allows `public|private` for visibility (no `internal`); `has_discussions` is not a PATCH field, so it is not offered; fork and star take the destination or acting account as `owner` because the write layer requires the target to be one of the connection's accounts.
Tests: `tests/unit/repos-write.test.js` — all nine write-contract checks through all three doors for every tool (284 tests), plus the extra D-1 checks (public names the risk, delete on a `pr-only` repository refused by the real guard, private by default, user vs org route, nothing-to-change refused, inverses). The contract helper gained a `profile` option and every test world now has a fake user authorization (for the `U` tools).
