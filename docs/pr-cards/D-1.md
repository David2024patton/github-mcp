Status: **IN PROGRESS — part 1 (reads) in PR #27; part 2 (changes) next.** Batch D (`docs/designs/BATCH-D.md` §3, §4 D-1).
Prerequisite: C-2. Risk area: repository settings (part 2). No migration. The card is built in two PRs to stay under the size limit:
part 1 = the seven read tools, part 2 = the thirteen change tools.

## Drift check A

| Card assumption | Actual | Kind | Correction / test |
|---|---|---|---|
| Read tools can call GitHub | The dispatcher gave `credentials` only to write tools, so `githubFor` would fail in a read | semantic (ours) | `createDispatch` now hands `credentials` (and an optional `sleep`) to every tool; `src/tools/github-read.js` turns any failure into the plain sentence of `explainGithubError` |
| `github_repo_list` also reads `GET /user/repos` (U) | An installation token cannot list a person's repositories; the user authorization arrives with Batch U | none (design says U) | Part 1 lists an organization (`/orgs/{org}/repos`) or a user (`/users/{username}/repos`) chosen from the stored account type; `/user/repos` waits for the U credential and is recorded in ROADMAP |
| `github_repo_get` summary is the repository summary form | The summary form drops merge options, rules and properties the design wants | none | The tool returns its own compact object (features, merge options, rules on the real default branch, custom properties); `fields` still applies |
| `github_repo_find` qualifiers | A caller could type `user:other` to search outside the connection | semantic (ours) | Qualifiers in the text are stripped; one search per allowed account with its own `org:`/`user:` qualifier |
| Stats endpoints answer 202 while computing | Confirmed in the vendored description | none | `requestStats` asks at most 3 times, then says "GitHub is still computing; try again in a minute." (tested) |
