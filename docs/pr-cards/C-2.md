## Drift check A

| Card assumption | Actual | Kind | Correction / test |
|---|---|---|---|
| Tools carry `area`, `audience`, compact membership | Only name, description, schema, annotations and (writes) declarations existed | none | Optional `area`, `audience`, `compact`, `guidance` on tools (`defineWrite`, `defineRead`, plain read tools). The area defaults to the second word of the name. **Audience is now required on every tool and is compared with the catalog's Audience column by `npm run check`** |
| `github_call` is a read tool with Safety "as the tool" | The dispatcher only ran tools marked read-only or defineWrite | semantic (ours) | A third kind, a *runner* (`passthrough`), hands the call back to the same dispatcher, so arguments, profile visibility, production switch, protected list, people, spend, change log and result rules all apply to the inner tool. The runner itself is annotated `readOnlyHint: false, destructiveHint: true` (it can run changes). Door 3 of the write-contract helper now runs every write-contract test through `github_call` |
| `github_batch` takes any calls | A change inside a batch would skip its preview/confirm flow | semantic (ours) | Refuses (before running anything) any call that is not a read tool the caller can see; the meta-tools cannot be called inside a batch or through `github_call` (no recursion) |
| Compact listing = meta-tools, whoami, API search, workflows | The API search and workflow tools do not exist yet | none | Compact = tools marked `compact`; today the four meta-tools, `github_whoami` and `github_get_result` (a handle must be readable from a compact list). Later cards mark theirs |
| Token counts use a pinned tokenizer | None installed | none | `gpt-tokenizer` 3.4.0 added as an exact-pinned dev dependency; counts are of exactly what `tools/list` sends (including annotations) |
| Listing descriptions start with PRODUCTION / SPENDS MONEY | Descriptions were stored as written | none | `listedDescription` adds the prefix in `tools/list` (and the 160-character budget counts it) |
| `?listing=` override | | none | `/api/mcp?listing=catalog|compact` overrides the connection's listing; any other value is ignored. A tool hidden from the list is still callable by name if the profile allows it |
| Default response on a 100-item fixture ≤ 8 KB | Enforced by the result rules (C-1) | none | Covered by `read-pipeline` tests rather than a script |

## Built

- `src/core/registry.js`: `LISTINGS`, `listedDescription`, `listedTool`, `toolsForListing`. `src/core/mcp-server.js`: listing per connection and the override; annotations are listed.
