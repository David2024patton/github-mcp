## Part 1 — read-only environment tools (#49)

- New `src/tools/environments-read.js`: `github_env_list`, `github_env_get`, `readEnvironment`, `protectionView`. `GET /repos/{owner}/{repo}/environments` with page/max/total and explicit possible-next-page; `GET /environments/{environment_name}` (404 only means absent).
- `protectionView` projects review identities, wait timer, self-review, branch-policy mode and custom protections; never conflates an unknown protection rule with an unprotected state.
- `github_env_get` fetches the distinct `/deployment-branch-policies` endpoint when custom policies are enabled (returns branch and tag patterns); reports cap at 100.
- `github_env_list(includeCounts)` asks secrets and variables metadata endpoints per environment; returns counts or an explicit unavailable reason on 403/5xx, never a value or a guessed zero. Default omits these extra calls for efficiency.
- Integration `src/tools/index.js`; `tests/unit/environments-read.test.js`. Required outcomes: list paging/total, metadata counts/denials, explicit 404 vs 403, reviewers/custom protections, branch/tag patterns, validated GitHub routes, no POST/PUT/DELETE.

## Part 2 — settings writes (next PR)

- New `src/tools/environments-write.js`: `github_env_save`, `github_env_delete` using `defineGithubWrite`; normalize GET into writable timer/reviewers/branch-policy fields; merge **only specified** options. Never copy read-only nodes to PUT.
- `PUT /repos/{owner}/{repo}/environments/{environment_name}`; `DELETE` at same route. Separate branch/tag pattern CRUD must use its own endpoints, not be smuggled into environment PUT. Any unsupported custom protections: refuse instead of silently disabling.
- Real production classification for the existing environment; proposed new reviewers/timer must also be production. Delete is irreversible and confirm-always. Read-back compares the full preserved writable state, not only changed field. Missing/403/5xx read states must remain distinct.
- `tests/unit/environments-write.test.js`: three-door write contracts, preservation, clearing, declined previews, production classification, unsupported rules, 404/403, read-back mismatch, no leakage, no unsafe side effects.

## Part 2 implementation evidence (#50)

- `src/tools/environments-write.js` exports `github_env_save` and `github_env_delete` using `defineGithubWrite`. A policy merge copies reviewer IDs, wait timer and self-review settings from the actual GET; only supplied arguments change. `clearDeploymentBranchPolicy: true` explicitly sends null, since the shared argument validator does not support union types. The object setter and clearing flag cannot be combined. GitHub receives only supported PUT fields.
- Unknown custom protection rules or missing reviewer IDs stop a save before the API call. Contradictory protected/custom branch modes are rejected. Existing or proposed required reviewers/wait make a change production; default production environment names remain protected. Delete is confirm-always, irreversible and lists lost secrets/variables.
- `tests/unit/environments-write.test.js` runs nine-check contracts through all three doors with mismatch, replay and protected-resource fixtures. Additional tests verify unaffected settings, explicit clearing, proposed production, unsupported rules, 403, contradictory modes and no mutation on refusal.
- Commands: `npx vitest run tests/unit/environments-write.test.js`, `npm run check`, `npm test`, `npm run test:shapes`, `npm run test:db` (in CI). The exact-head aggregate `ci` must pass.

## Part 3 — deployments and additional policy endpoints

**Part 3b — guarded deployment writes (#52).** `src/tools/deployments-write.js` implements create and status via `defineGithubWrite`; the create POST always uses `auto_merge: false`, never bypasses required contexts, rejects unverified results including 202 and classifies both ref/environment. Status first GETs the deployment ID for real ref/environment/production flag, POSTs once, then confirms the exact status ID. `tests/unit/deployments-write.test.js` includes three-door write contracts, preview production refusals, missing IDs, 202, mismatch and absence of unsafe side effects. Next: separate branch/tag policy endpoints; G-4 remains IN_PROGRESS.

**Part 3a — deployment reads (#51).** `src/tools/deployments-read.js` registers `github_deploy_list` with ref, SHA, task and environment filters and truthful page boundaries. It reads the most recent status through `GET /deployments/{deployment_id}/statuses?per_page=1` for each returned record unless opted out, returns null when absent, and never writes. `tests/unit/deployments-read.test.js` checks filters, status read, absent status, skip mode, access failures, valid fake-GitHub routes and zero mutation. No migrations. Deployments and branch/tag policies still require guarded writes before G-4 can close.


- `src/tools/deployments.js`: `github_deploy_list`, `github_deploy_create`, `github_deploy_set_status`; read actual deployment by ID, production from real ref/environment, no deployment dispatch on preview; 202 merge response is **not** a created deployment.
