# 2026-10-24 — HARD-1 part A: sign-in steps and App keys

**Sign-in steps.** Before: every open sign-in step counted toward one shared limit of 200, so one app opening many sign-in links could block
everyone for 10 minutes. Now the shared limit is 5000 and each app gets its own limit of 20 open steps (`GITHUB_PUBLIC_MAX_OPEN_FLOWS_PER_CLIENT`),
so an app that opens too many only blocks itself. Expired steps never count and are cleaned up when that app starts a new sign-in.
Small deliberate difference from the card: the two built-in pages (My connection, Delete my data) have their own cap of 200 each instead of 20,
because they are shared by every person; a cap of 20 there would let a few visitors lock out the page for everyone, which is the problem being fixed.

**App keys.** Before: each person's store kept its own copy of the App's sealed keys, refreshed only at their next sign-in. Now the connection
route reads the shared copy first (`rootApps` in `createCredentials`); the person's own copy remains as a fallback and for older code paths.
A replaced App key reaches every connected person at once. Remaining readers of the per-person copy (two read-only tools) are unchanged.

**Tests:** DB tests "HARD-1 sign-in steps ..." (cap of 20, setting, expired steps, built-in pages) and "HARD-1 one shared copy of the App keys"
(replace the key in the shared copy; an already-connected person signs with it at once).
