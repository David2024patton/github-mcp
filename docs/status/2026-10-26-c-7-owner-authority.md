# 2026-10-26 — C-7 owner-authorized override parity and gap remediation

**Owner direction:** Cortiware's authorized merge was refused by our custom MCP although the official connector completed it after approval. Explicit owner authority should pass through the product when GitHub accepts, not be blocked by the MCP's own guesses. This specific external incident was not reproduced against Cortiware or its live data, and no third-party repo was modified.

**Identified cause:** `src/tools/rule-override.js` previously used `skippedRules().length>0` to decide whether even to attempt a GitHub bypass; a failed scan not in the local rules list could therefore turn the request into an ordinary merge and get refused. Separately, `github_workflow_merge_when_green` preflight required green CI and did not accept explicit `overrideRules` and `overrideReason`. The owner-approved C-7 source fixes both gaps. When a person authorizes a deliberate override and local rule discovery is empty, GitHub adjudicates the bypass; normal merges remain checks-bound. The compact workflow forwards deliberate authorization to the existing guarded writer, which still applies user-chosen protected-resource policy, exact head, full/everyday and production authentication, master-token scope, confirmation, once-only journal and provider readback. Pending background merges are not reported as merged.
