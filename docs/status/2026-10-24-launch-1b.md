# 2026-10-24 — LAUNCH-1 part B: load test, cost estimate, limits page

**Built (PR open):** a local load test, an estimated monthly hosting cost on the owner page, and a plain-words `/limits` page.

**Load test numbers** (50 people, 10 at once, each signs in then makes 5 `github_whoami` calls; fake GitHub, throwaway local database,
one laptop-class machine, so these show our own code's behaviour, not Vercel or Neon speed or price):
- Errors: 0 of 50 sign-ins and 0 of 250 calls.
- Sign-in (register, authorize, approve, token): typical 1.0 s, slowest 5% under 1.5 s, worst 1.6 s.
- Assistant call: typical 0.39 s, slowest 5% under 0.56 s, worst 0.59 s.
- Database: 50 people, 50 identities, 50 clients created. Whole run about 8 s.
Run it again with `npm run test:load` (`-- --people 20 --at-once 5` for a smaller run). It refuses any address that is not the local fake.

**Bug found and fixed:** with many first-time sign-ins at once, two of them tried to create the same database function together and
Postgres refused one ("tuple concurrently updated"), so some people saw "temporarily unavailable". The setup step now retries that one
refusal a few times (`retryConcurrent`). Real Neon would have shown the same thing on a busy launch day.

**Cost estimate:** shown on the owner setup page under "Public usage" as about $X a month, from the last 7 days of call counts scaled
to 30 days. Rate is `PUBLIC_COST_PER_1K_CALLS_CENTS` (default 5 cents per 1,000 calls, a rough placeholder to match against the current
Vercel and Neon price lists). A warning line shows at or above `PUBLIC_COST_ALERT_CENTS` (default 2000 = $20). It is an estimate, not a bill.

**Limits page:** `/limits` lists per-app and total call rates, sign-in rate, saved-result size and age, background jobs and the extra-names
cap, read from the same settings the server enforces. Linked from My connection.
