# 2026-10-26 — C-5 PR/CI critical-path benchmark and read-overlap source

Owner directed making the GitHub MCP exceptionally fast for everyday development workflows, not merely isolated tools. C-5 plan was committed first and indexed before code. It reduces independent read request latency in `src/github/ci-state.js`, `src/tools/pulls-read.js`, `src/tools/workflows-pr.js`: rules, classic protection, check runs, and statuses can start concurrently after the known PR base/head; review GraphQL and CI can run concurrently; stack membership and PR status can run concurrently. All reads continue through existing authorized client/dispatcher, and provider writes/protections/confirmation are untouched.

On the previously deployed `live` commit `607bd30fb3314fbf4c0b04092ccdb5d30a57e963`, one live read of closed #415 took 2,680 ms; an open #409 read 3,610 ms; compound #409 status 7,541 ms through the existing custom connector. These are **individual uncontrolled samples**, affected by handshake, network and GitHub. They are a reference, **not** a baseline in a statistically controlled experiment or proof of the eventual gain.

`scripts/benchmark-pr-critical-path.mjs` repeats a deterministic synthetic four-read CI and two-read PR-status path on fake provider delays; tests in `tests/unit/pr-critical-path-perf.test.js` assert four parallel independent CI requests, guard behavior when evidence is unavailable, and simultaneous stack/status launch; `tests/unit/pulls-read.test.js` asserts the real fake-GitHub/Oktokit dispatcher overlaps independent review/CI while validating request shapes. Benchmark measures scheduling/critical path only, never real-client latency or full commit/build/release time. No real provider mutation or early production release is authorized or claimed.
