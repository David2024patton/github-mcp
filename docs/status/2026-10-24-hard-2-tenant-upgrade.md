# 2026-10-24 — fix: people who signed in before a release did not get its new database columns
**What went wrong:** the release that carried GOD-5 added two columns (`allow_changes`, `allowed_repos`) to each person's account table. Those tables are only built when a person first signs in, so the two existing people (Chris's connections) did not have the columns. After the release, `github_whoami` and every change (the safety check reads the new column) failed with "a safety check could not be completed"; plain reads still worked. Found by the live acceptance run, confirmed by reading the database structure (read-only): both older tenant schemas lacked the columns.
**Fix (this PR):** the first request for a person on each server instance now re-runs the table setup, which is additive (`IF NOT EXISTS`) only. A failure is retried on the next request and never blocks a read. Test: a person's table is made to look old (columns dropped); opening the connection restores them and the account list works again (`HARD-2` in `tests/db/pub-6-public-connect.test.js`).
**Until the next daily release carries the fix:** whoami and changes fail for existing people; reads work. An immediate repair is two additive `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` statements on the two existing person schemas; the agent environment refused to run them (production database change), so this is on `docs/OWNER-CHECKLIST.md` as an optional shortcut.
**Lesson for future releases:** any new column in `src/db.js initSchema` now reaches existing people automatically on their first request.
